3. CORE ARCHITECTURE
================================================================================

BACKTESTING SYSTEM:
  Input: Historical cryptocurrency price data (4H klines)
  Process: Two-phase AI agent evaluation
  Output: Accuracy scores with cost tracking
  
AGENTS USED:
  1. Technical Analysis Agent (gpt-5-mini)
     - Analyzes 7 days of historical data
     - Predicts support/resistance levels
     - Makes price movement forecasts
     
  2. Reviewer Agent (gpt-5-mini)
     - Evaluates technical analysis accuracy
     - Compares predictions to actual outcomes
     - Provides score and feedback
     
  3. Trading Agent (gpt-5-mini)
     - Reference implementation
     - Makes trading recommendations

EXECUTION METHOD:
  - OpenAI Batch API (two phases)
  - Async support for parallel execution
  - Cost tracking built-in

================================================================================
4. BATCH PROCESSING WORKFLOW
================================================================================

TWO-PHASE BATCH APPROACH:

PHASE 1: TECHNICAL ANALYSIS
  Step 1: Generate requests
    - Create sliding windows (stride=3 days)
    - Generate JSONL file (batch_tech_requests.jsonl)
    
  Step 2: Preview & validate
    - Check for policy violations
    - Estimate token counts
    
  Step 3: Submit batch job
    - Upload to OpenAI
    - Track batch_id
    
  Step 4: Monitor and download
    - Poll job status
    - Download batch_tech_results.jsonl
    
  Step 5: Process results
    - Parse results
    - Extract analysis
    - Save to tech_analysis_results.json

PHASE 2: REVIEW
  Step 6: Generate review batch
    - Load tech analysis from Phase 1
    - Create reviewer prompts
    - Generate batch_review_requests.jsonl
    
  Step 7: Submit and process
    - Submit batch job
    - Monitor status
    - Download batch_review_results.jsonl
    
  Step 8: Final combination
    - Combine tech + review results
    - Calculate total costs
    - Generate backtest_report.json

KEY FUNCTIONS:
  - preview_batch_requests() - Safety check before submission
  - generate_batch_requests_file() - Create Phase 1 JSONL
  - submit_batch_job() - Submit to OpenAI
  - check_batch_status() - Monitor progress
  - download_batch_results() - Retrieve results
  - process_batch_results() - Parse and organize
  - generate_review_batch_from_tech_results() - Create Phase 2
  - process_review_results() - Final combination

5. DATA PROCESSING
================================================================================

SLIDING WINDOW STRATEGY:
  - Analysis period: 7 days (agent sees this)
  - Review period: 7 days (actual outcomes)
  - Stride: 3 days (overlapping windows)
  - Total period: 2025-06-01 to 2025-11-03 (155 days)
  - Total windows: ~48
  - Overlap: 11 days between windows (maximizes data usage)

DATA SOURCES:
  - MySQL database with 4H candlestick data
  - Fields: open, high, low, close, volume, funding_rate
  - Access via get_latest_price() function
  - fetch_backtest_data() - Combines analysis + review data

12. KEY INSIGHTS
================================================================================

ARCHITECTURAL PATTERNS:
  1. Two-phase design separates concerns
     - Phase 1 focuses on analysis generation
     - Phase 2 focuses on evaluation
     - Allows independent error handling
     
  2. Sliding window strategy maximizes data
     - Overlapping windows increase sample size
     - Better statistical significance
     - Stride parameter controls overlap
     
  3. Cost awareness built throughout
     - Estimates before running
     - Tracks actual usage
     - Prevents budget surprises
     
  4. Metadata tracking for correlation
     - custom_id maps requests to windows
     - Enables result reconstruction
     - Supports partial recovery
     
  5. Async/parallel execution support
     - Direct execution: concurrent for speed
     - Batch API: asynchronous for efficiency
     - Both modes supported

UNIQUE FEATURES:
  - Backtesting with hindsight (evaluates predictions after outcomes known)
  - Two AI agents (one generates, one evaluates)
  - Overlapping sliding windows (overlapping by 11 days)
  - Comprehensive cost tracking
  - Failure recovery mechanisms
